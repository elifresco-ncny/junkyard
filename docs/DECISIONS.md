# Decisions

## M0
- JUCE pinned to **8.0.17-security** (latest 8.x; JUCE 9 exists but plan says 8). Catch2 v3.16.1. Fetched as tarballs because `git clone` into `build/_deps` is blocked by the sandbox (and flaky over HTTP/2).
- Code split: `junkyard_dsp` (no UI deps, juce_dsp only), `junkyard_core` (processor, state, UI), plugin target (`PluginEntry.cpp` only). Tests/tools link `junkyard_core`.
- Artifacts live in `build/Junkyard_artefacts/RelWithDebInfo/...` (Ninja single-config still adds the config dir).
- AU pluginval runs post-install (macOS must register the component first); VST3 pluginval runs pre-install.
- Owner is away: milestones M0→M9 run back-to-back without waiting for feedback; M10 skipped.

## M1
- Latency @48k = 2N (1024) + 10 ms (480) = **1504 samples**; @44.1k = 1024+441; @96k = 2048+960. Verified by impulse tests (every section combo/order, 4 rates, 6 block sizes).
- Sections that are off are delayed by their own fixed latency; enabling a section holds the dry path for `latency` samples (pipeline fill) then crossfades over 20 ms; disabling crossfades over 20 ms then stops processing. Order change = 10 ms duck down, swap, 10 ms duck up.
- Enum display strings use plain ASCII ("Digital > Tape").
- Wet-path `Mix` crossfade uses dry from *before* input gain.
- After bypass or a NaN trip the engine "prewarms": resets sections and holds on dry for L samples before fading wet in.
- Bitrate param is normalized 0..1 (display depends on the Mode via `ModeProbe`).

## M2
- Own FFT instead of juce::dsp::FFT (deterministic, no JUCE dependency in the DSP lib, avoids unknown inverse-scaling conventions). 2N-point complex FFT is ~4x the work of the N/2 trick but costs <1 % CPU total, so kept simple. Orthonormal scaling (sqrt(2/N) both ways) so coefficient energy == time-domain energy.
- Codec latency verified = 2N by impulse test through the *quantising* codec at 320 kbps.
- Bit-cost model: zeros above the last non-zero bin are free (mimics MP3's rzero region); bit reservoir (max 4088 bits, 50 % usable per frame).
- Header bits (32) deducted once per frame. Budget split between channels by perceptual entropy, 10 %..90 % clamp.
- Intensity stereo: coded channel D = M scaled to carry L+R energy (gain capped at 3), decoder re-pans with sqrt(r), sqrt(1-r), r quantised to 7 steps.
- Codec RNG is reseeded to a fixed seed on reset (determinism).

## M3 — calibration (synthetic signals: pink noise, castanets, chord, speech-like, mix; `testaudio/` was empty)
Tools: `tools/reference/{synth,make_refs,compare,tune,metrics}.py`; results in `docs/CALIBRATION.md`.
- **Cutoff table** (kbps → Hz): 8→2000, 16→3400, 24→4300, 32→5500, 48→7600, 64→10900, 80→14000, 96→16800, 112→16900, 128→16900, 160→17500, 192→18900, 256→19500, 320→20000. Matched to what LAME *actually measures* (-20 dB bandwidth), not to its nominal lowpass (e.g. LAME at 32 kbps = ~5.5 kHz, not 7).
- Coordinate-descent over the constants vs LAME's zeroed-cell % → mean error 0.54 → 0.21. Adopted: c0=0.5, c1=1.5, c2=1.0, c3=5; noise offset 1.5 dB, tonal offset 6.5 dB (+bark); outer passes 6, scalefactor step 4 dB, reservoir use 0.5, ATH offset 0. (Plan's starting values were noise 5.5 / tonal 14.5 / 2 passes / 2 dB.) The 4 dB sf step and 6 passes make the allocator spread bits like LAME's many-iteration loop; CPU is still ~0.8 % of a core.
- Result: 42/50 LAME rows within bw ±10 % and zeroed ±30 % (remaining misses: tiny-zeroed rows where ±30 % is a fraction of a percent, plus LAME's non-monotonic lowpass at 24/96 kbps). Hole *patterns* look LAME-like (see PNGs); Junkyard holes are slightly more band-block-shaped, LAME's more speckled.
- Side-channel energy and pre-echo track LAME within a few dB (we have no block switching, so pre-echo is slightly higher at low rates: authentic to the brief).
- AAC reference (ffmpeg native encoder) is used only as a rough guide for Stream mode (M4): its bandwidth at 32/64 kbps is much lower than MP3's.

## M4
- Stream core cutoff <64 kbps: 5.5 kHz (6 kbps) .. 8 kHz (64 kbps); SBR patch tiles [fc/2,fc) up to min(2fc, 16 kHz), 5-band coarse envelope (3 dB steps) refreshed every 2 frames, applied in L/R after stereo decode. >=64 kbps uses the MP3 cutoff table x1.02, 6-bin taper. Tuned by spectrogram look only (no HE-AAC reference available).
- Parametric-stereo-lite (<32 kbps): intensity stereo for *all* bands + small cross-bin decorrelation on R.
- Glitch: Gilbert-Elliott per frame (pGB = .25 g^2, pBG = .6 - .4 g). MP3 flavour: per burst either a mute or a frozen last-good frame (stutter). Stream: PLC = last good spectrum x 0.6^run with random signs; buffering gap 150-600 ms starts with p = .01 + .08 g^2 per burst and has a >=2 s cooldown (first pass was far too frequent). Broken: random event per bad frame (history frame, half-band loss, bin reversal, +12..20 dB burst, freeze).
- Broken rectangular-window buzz probability = .003 + .03(1-br)^2 + .02 g^2 per frame (first pass .01+... was too busy).
- Fades: events act on MDCT spectra, so the sine-window overlap gives a >=1 hop (10.7 ms @48k) fade in/out automatically.

## M5
- Saturation makeup is referenced to a 0.25-amplitude signal (gain = 0.25 / tanh(0.25·drive)) so turning Saturation up keeps typical levels equal (synth mix RMS stays within 2 dB from 0 → 100 %) while peaks compress. Saturation stage is skipped when Saturation = 0 (exact transparent).
- Age = 0 skips the age lowpass; azimuth drift is zero-mean (±0.1 ms, +/- on L/R) so the mean latency per channel is exactly 10 ms.
- Dropouts: one event at a time (shared timing, ±20 % length/depth per channel), only the signal is dipped, hiss continues.
- Pink noise: Kellet filter normalised to unit RMS at prepare time.
- Crusher: Rate param at its max (≥47.99 kHz) = bypass at every host sample rate (so Crunch with defaults at 96 kHz isn't silently resampled).

## M6
- The engine now runs on a **fixed 64-sample tick grid aligned to a global counter**; chaos advances only on grid boundaries. Result: output is bit-identical regardless of host block size (tests: 512 vs 97 vs 1-sample blocks).
- Reseed-on-play does a *full* `engine.reset()` (not just RNG reseed) – otherwise LFO phases/MDCT FIFO/reservoir would make exports differ. Costs nothing audible (dry path is also reset; host PDC covers it).
- Chaos spells: every 2–6 s a check with p = .15 + .7·chaos; boost target = chaos·(0.4..0.9), 150 ms smoothing.

## M7
- UI is drawn in a fixed 960×560 "design space" component scaled with an AffineTransform; the editor size = design × scale.
- Shift-for-fine applies when held at mouse-down (JUCE's slider can't change sensitivity mid-drag without a jump).
- Scope: the audio thread pushes one 64-bin summary per codec frame into an SPSC ring only while an editor is open (atomic flag); the UI pulls at 30 fps into a 480-column circular image.
- Fonts: Bebas Neue and Share Tech Mono, both SIL OFL (licence in assets/fonts/OFL-BebasNeue.txt; Share Tech Mono is OFL as well).
- pluginval with GUI tests passes at strictness 5 (opens/closes editor); strictness 10 in M9.

## M8
- Undo/redo is an own small stack of parameter snapshots (30 deep), not `UndoManager` on the APVTS: with an UndoManager every host-automation change would be recorded as an undo step.
- Preset "modified" flag = any parameter differs (>0.002 normalised) from the loaded preset's values; the reference is recomputed from the preset name after a state restore, so a saved Live set shows `*` correctly.
- `setCurrentProgram` is ignored for 3 s after `setStateInformation`, so hosts that reset to program 0 after restoring can't clobber the saved settings.
- Preset loads apply every parameter (missing = default) inside change gestures.
- Loudness trim is baked into each preset's `output_gain`.

## v0.2
- Parameter IDs are JUCE string-hash IDs (no `JUCE_FORCE_USE_LEGACY_PARAM_IDS`), so removing `chaos`/`tape_dropouts` does not shift the remaining parameters in Live. Existing automation of the two removed parameters simply disappears.
- **Tone = −3 dB point.** The old Age filter (Q 0.6 biquad + 1-pole at 1.4×) had its −3 dB point at ~0.7× its nominal cutoff. So the filter's nominal cutoff is now 1.43 × Tone (the −3 dB point lands on the displayed value, verified by test), and migration/presets map old Age to 0.7 × the old nominal cutoff so old material sounds the same.
- **Azimuth uses an all-pass fractional delay**, not the cubic interpolator: the Catmull-Rom interpolator low-passes the signal whenever the fractional delay is non-zero (measured −1.3 dB above 10 kHz at Age 100), which is exactly the HF loss Age must not have. Latency is unchanged: the main tape delay is `base − 8` and the azimuth stage adds 8 ± drift samples (exactly 8, bit-exact, at Age 0).
- **Mono-sum of Age (v0.2.1).** Azimuth drift is ±0.01 ms per channel (0.02 ms L/R) at Age 100. The v0.2 value (0.25 ms) put the mono-sum comb's first null at 2 kHz, so Age dulled the highs again in mono or with Width narrowed. Real tape azimuth error is tens of µs. At 0.02 ms the null is above 20 kHz; the measured mono HF change is −0.09 dB, and the test limit is back to ±2 dB. Age's character now comes mainly from level wobble and signal-dependent grain.
- Tone and head-bump coefficients are updated on a fixed 16-sample cadence from per-sample smoothers (block-size independent output was lost when they were updated per chunk).
- Limiter: knee 0 dBFS, ceiling +6 dBFS. Test peak bounds updated; Output (up to +12 dB) can still exceed that after the limiter by design.
- Broken "loud burst" event: +6…+12 dB (was +12…20). Other Broken corruptions (band ±6–20 dB) unchanged as instructed.
- Old-vs-new Age comparison renders: the v0.1 binary could not be rebuilt in this session, so `renders/v0.2/age/` holds the new behaviour only (Age 70 with Tone off, Age 70 with Tone 7 kHz, Age 0 with Tone 7 kHz).

### Noticed, not changed
- Section enable still holds the dry signal for the section latency while the pipeline fills (a brief dip on toggling Codec/Tape on).
- Stream noise-fill and SBR use the same RNG stream as Swirl, so changing Swirl re-rolls unrelated random events (harmless; deterministic).
- Presets that include Hiss > 0 are intentionally not silent on silent input.

## v0.3
- **Crunch removed in v0.3: owner considers it redundant** (the codec and other plugins already do bit/rate reduction). The frozen IDs `crush_on`, `bits`, `downsample` are gone; the migration drops them. The `order` ID and values are unchanged, only the display text.
- **Hiss gate rule.** Hiss is audible only while the host transport is playing **or** audio is coming into the tape section (any sample above -80 dBFS within the last 0.5 s); 50 ms linear ramp, multiplied into the hiss gain only. Hosts without position info count as playing. Reason: Live keeps calling `processBlock` while stopped, so Hiss played forever.
- **Level-tracking saturation makeup.** The static makeup was calibrated at about -12 dBFS; tanh compression dropped loud material by up to 8 dB and over-boosted quiet material by up to 5 dB. Added open-loop correction `sqrt(msIn/msOut)` from two 300 ms stereo-linked mean-square followers (stage input vs stage output after the DC blocker), clamp +-12 dB, 50 ms smoothing, hold below -70 dBFS. Open loop cannot oscillate. Hiss and Age sit after the stage and don't affect it. Side effect: after a large level *drop* the correction needs a few hundred ms to settle (only the step *up* is bounded by the tests, as specified).
- **Broken level trim.** Broken at 64 kbps was +1.2..+2.3 dB hotter than the input (corrupted bands jump +-6..20 dB in amplitude, so the power mean rises). FIX_PLAN_2 required +-1 dB, so Broken now has a slow 1 s energy follower (input spectrum vs corrupted output spectrum, frame rate) that can only reduce the gain (0.5..1.0). The corruption character is unchanged; sustained loudness is matched. MP3 and Stream were already within -0.6 dB.
- **Flutter** +-0.6 % at 100 % with a ^1.3 curve; the peak measured by phase demodulation is 0.77 % (the 2nd harmonic adds about 30 %). At the 15 % default it is 0.066 %. Delay excursion is about 6-9 samples at 48 kHz, so the 2-sample clamp never bites.
- **Age design and control-ownership table.** Each sound belongs to one control: slow pitch = Wow; fast pitch = Flutter; constant noise floor = Hiss; static high cut = Tone; drive/compression/head bump = Saturation; gaps/mutes/repeats/corruption = Glitch; short level dips/dropouts = nobody (rejected in v0.2); level wobble, signal-dependent grain, HF wander and print-through = Age. Measured at Age 100 (tests in `tests/test_v03.cpp`): pitch deviation 0.1 cent (azimuth only), longest dip below -6 dB 0 ms (min -3.4 dB), envelope std 1.6 dB, 8-16 kHz band std 1.6 dB, grain -29 dB re signal, print-through echo at 1.34 s and -32 dB, > 8 kHz long-term change +0.02 dB stereo / -0.28 dB mono, RMS +0.4 dB (no makeup needed). The raw value-noise wobble rarely reaches +-1, so it is scaled by 1.6 and clamped so the stated +-3 dB is actually reached (envelope std would be 1.0 dB otherwise). The print-through delay wanders +-40 ms at a very slow 0.04 Hz: faster wander would pitch-shift the ghost by up to 2.5 %, which breaks the "Age moves no pitch" rule. Print-through is added after the wobble, so the ghost is a clean copy of the tape input; it is always written to its buffer, even at Age 0.
- **Mode memory only on UI clicks.** Writing other parameters from a mode-change listener would fight the host (automation or preset loads would trigger writes, and Live shows "automation overridden" on those parameters). `switchModeFromUi` runs on the message thread from the Mode switch's click handler, uses begin/endChangeGesture so Live records and undoes it, and stores values in a `MODE_MEMORY` ValueTree child (session only; stripped from presets, cleared on preset load, Init, Scrap and undo/redo).
- **Preset removals.** *192k Almost Fine* (redundant with Init and 128k Car Stereo) and *Ghost Stream* (redundant with Underwater Stream) removed. A saved Live set that names a removed preset just loads its stored parameters.
- CPU (RelWithDebInfo, 48 kHz / 128 block, Age/Wow/Flutter 100, Sat 60, all sections on): MP3 1.26 %, Stream 1.01 %, Broken 0.90 % of one core; 20 instances 19.2 % total.

### Noticed, not changed (v0.3)
- After a large level *drop* with Saturation up, the level-tracking makeup briefly over-boosts (a few hundred ms), because the followers are slow by design.
- `Section` enable still holds the dry signal for the section latency while the pipeline fills.
- The print-through ghost is a bit dull on very short sounds because it is band-passed 150 Hz-3 kHz per the spec.

## v0.4 (FIX_PLAN_3.md)

### No level followers anywhere (decision 1)
- Removed the tape saturation follower (`msIn/msOut/gDyn`) and the Broken-mode follower (`brkIn/brkOut/brkGain`). Every gain in the signal path is now a pure function of the parameters, plus one stored calibration that changes only when the user presses Learn.
- **Audit of `src/dsp`** (grep for follower / envelope / rms / match / gain-from-average): `Tape` (no followers left; the hiss and Age envelopes only drive *added* noise, never a gain on the signal), `TapeAge` (envelopes drive the four Age parts, same rule), `CodecEngine` (Stream noise fill is per frame and energy-relative with no long-term memory; Broken uses the fixed trim below; the bit reservoir is codec behaviour, not a level gain), `SafetyLimiter` (memoryless tanh waveshaper above 0 dBFS), `JunkyardEngine` (smoothers and the fixed crossfades only). Nothing else keeps a running level.
- **Broken trim.** `brokenTrimDb(bitrateEff, glitchEff)` = bilinear lookup in `BrokenTrimTable.h` (9 bitrates x 3 glitch values), applied where `brkGain` was, smoothed with a one-pole over about 4 frames (only so parameter changes do not step). The table is generated by `junkyard_calibrate broken`: Broken at each grid point (Swirl 25 %, HF Loss 0, trim forced off), pink / drums / full mix at -18 and -8 LUFS, 10 s each, fixed seeds, `trim = -mean(out - in)` in BS.1770 LUFS. **The table never boosts** (trim <= 0): below about 3 kbps Broken is *quieter* than the input, v0.3's follower never turned that up, and boosting the few surviving bands would be a new behaviour. Values (dB), rows Glitch 0 / 50 / 100 %, columns Bitrate 0, 1/8 ... 1: `0 0 0 -3.9 -4.2 -3.5 -3.2 -2.6 -1.2 / 0 0 0 -4.2 -4.9 -3.6 -4.0 -3.5 -2.7 / 0 0 0 -4.4 -4.9 -4.6 -3.9 -4.2 -3.1`. The existing +-1 dB test (every mode at 64 kbps, Swirl 0) still passes.
- **"No level memory" tests** (`tests/test_v04.cpp`): the tape alone (Drive 50 %) gives the same level in seconds 3-8 after a 1 s burst at -2 dBFS as without it (+-0.05 dB, measured 0.00); Broken at 32 kbps +-0.5 dB, with the trim and with the trim forced to 0 (it has no memory either way).

### Hiss follows the audio (decision 2)
- Removed `EngineParams::transportRunning` and the gate. The transport is now used only for reseed-on-play.
- Sidechain: `max(|yL|, |yR|)` right after the delay-line read and before Drive (time-aligned with the output, so hiss cannot start before the music; it is not the 10 ms early input). Detector: one-pole, attack 3 ms, release 100 ms. Every 16 samples: `relDb = min(0, envDb - knee)`, `fade = clamp((envDb + 80) / 10)` (gone below -80 dBFS), target ramped linearly over the 16 samples; the pink generator is skipped when the gain is exactly 0.
- **Deviation: knee -24.5 dB instead of -30.** The plan's detector reads about 5 dB above the RMS of noise-like music (a fast attack / slow release follower rides the peaks of pink noise), so with a -30 dB knee, -40 dBFS pink gave only 5 dB less hiss than -10 dBFS pink. With -24.5 dB (constant `kHissKneeDb` in `Tape.cpp`) it gives the specified 10 dB: measured -30.09 dBFS (pink -10) vs -40.86 dBFS (pink -40). For a sine burst at -10 dBFS: hiss exactly 0 before the burst reaches the output, -30 dBFS during it, exactly 0 within 1 s after it.

### Drive (decision 3)
- ID `saturation` kept (display name Drive, default 0). `driveDb = 30 * v`. The stage lives in `src/dsp/DriveStage.h` (Tape, `junkyard_calibrate` and the Learn analysis run the identical code). Filters, ADAA tanh and asymmetric bias unchanged; the old makeup that was inside the stage is gone.
- **Alias level** (5 kHz sine at -6 dBFS, Drive 100 %, 48 kHz): fundamental -4.0 dBFS, largest non-harmonic component -23.1 dBFS at 23 kHz (19.1 dB below the fundamental). No oversampling added, as planned.
- **Loudness** is BS.1770-4 K-weighting, ungated (`src/dsp/Loudness.h`), tested at 44.1 and 48 kHz. (The plan's "-20 dBFS" for the 997 Hz check is an RMS level: -20 dB RMS in one channel reads -20 LUFS, in both -17.)
- **Calibration** (`junkyard_calibrate drive`, `docs/DRIVE_CAL.md`): five deterministic synthetic materials (`src/dsp/Corpus.h`: pink; drum loop; bass; full mix; mastered mix = full mix -> tanh x2 -> brickwall limiter pushed to -8 LUFS, crest 9.2 dB), 8 s each at 31 drives x 37 loudnesses. `T[d][L]` = mean makeup over materials; `D[d]` = minimax over L in [-26, -6] and all materials; clamped +-24 dB, d = 0 exactly 0. Residual error of the default row (worst case over the range and materials): +-3.0 dB at +6, +-4.9 at +12, +-6.8 at +18, +-9.1 at +30 (plan expected 2.5 / 4.4 / 6.4 / 9). The honest consequence: **the default curve is a hedge across levels; Learn is how to get it accurate**.
- Corpus choices the plan left open: the drum loop has the kick on every beat plus a syncopated 16th every second bar (levels: kick 1.0, snare 0.35 noise + 0.3 body, hats 0.2), pad chords cross-fade over 100 ms so the pad never drops out. With this loop the crest at -10 LUFS is 16.0 dB in, 4.0 dB at Drive 60 %, 2.1 dB at Drive 100 % (limits 5.0 / 4.0).
- **Deviation: `kDefaultL` = -14 LUFS, chosen as the integer L in [-26, -6] that minimises the worst |m - D| over all drives and materials** (the plan averages, over d >= 6, the L where T meets D; with these materials that L is about -10 at small drives and -15 at large ones, so a single average left 3 dB errors at high drive). **Deviation: the default-curve test allows +-2.5 dB, not +-1.0**: the five materials already differ from each other by up to 2.25 dB at the same loudness and drive (clipping affects peaky and flat material differently), so +-1.0 is not reachable with a single default row. Measured worst case 2.25 dB (`err@default` column of DRIVE_CAL.md). Learn accuracy is +-0.5 dB or better.
- **Run-time makeup** (control rate, 16 samples): `makeupDb = curve(d) + T(d, Lbase + delta) - T(d, Lbase)`, with `delta = Input now - Input at learn` (0 in default mode); the gain is linearly smoothed over 20 ms, over 200 ms when the published curve changes. Verified: with fixed parameters the applied gain is bit-identical on every sample after the first 50 ms, through silences, -40 -> -2 dBFS jumps and bursts.
- **Learn.** Capture (audio thread, `LearnCapture.h`): on the signal entering the tape section (after the codec in Codec > Tape, after Input and Low Keep always), whether or not Tape is on; 5 s buffer allocated in `prepareToPlay`; 100 ms chunks, a chunk whose peak is below -60 dBFS is rewound so silence is never learned; the first chunk with signal moves Waiting -> Recording; at 5 s the state becomes Analyzing and the audio thread stops touching the buffer. The audio thread owns every capture variable (the message thread only flips atomics and posts a start request). Message thread: a 20 Hz `juce::Timer` owned by the processor, started only while a learn is active (so it works with the editor closed and never runs idle); timeout 30 s wall clock (injectable clock for tests); on Analyzing it starts one `juce::Thread` that computes `Lcal` and `C[d]` for d = 0..30 with the same `DriveStage` (about 1 s; all allocation is on that thread); when done the timer joins it, publishes `{C, Lcal, inputDbAtLearn}` through a lock-free double buffer (`CalPublisher`, atomics, one version load per control tick) and writes the `driveCal` state property (`1;Lcal;inputDb;C0,...,C30`; never a parameter, stripped from user preset files, untouched by preset load / Init / Scrap, saved with the Live set, malformed values ignored). The job is stopped and joined in the destructor, in `releaseResources` and before `prepareToPlay` reallocates the buffer. A click while listening cancels; right-click offers Learn / Use default curve.
- Learn accuracy (tests, real processor): mastered mix and drums at -24 LUFS within +-0.5 dB at Drive 0 / 30 / 60 / 100 %; Input -6 dB after learning gives output = input - 6 dB within +-1 dB; a Learn finishing under 1-sample blocks causes no allocation on the audio thread and no level step beyond the 200 ms ramp.

### Wow and Flutter (decision 4)
- Wow peak speed `0.03 * w^1.5`, Flutter `0.015 * f^1.5`, scrape `0.0008 * f`, shapes unchanged. The 0.75 sine + 0.25 value-noise wow shape only reaches about 0.82 of its nominal speed deviation when measured, so the wow depth carries a fixed x1.2 (`kWowShapeScale`): measured Wow 100 = +-2.95 % at 0.9 Hz, Wow 20 = 0.26 %. Flutter 100 measures +-1.93 % at 7.8 Hz (the 2nd-harmonic term and scrape add to the nominal 1.5 %; the tooltip says "up to 2%" since v0.4.1).
- **v0.4.4: Wow depth scaled to 0.75x** (`0.0225 * w^1.5`, measured about +-2.2 % at 100 %) on owner feedback; presets were not re-converted, so they follow the gentler curve. The delay budget below only gets more headroom.
- Delay budget: azimuth is gone, so the main delay is centred on `base` (10 ms). Worst case at 100/100 (x1.2 wow, 48 kHz) is 480 + 430 + 22 = 932 samples, so `maxDelay` is 1.95 * base (936; plan 1.9 * base = 912 would clamp with the x1.2). Tested at 44.1 / 48 / 96 / 192 kHz for 60 s: zero clamps, delay inside [2, maxDelay].

### Age rebuilt (decision 5) - `src/dsp/TapeAge.h/.cpp`
Chain: delay line -> Drive -> [Age: Mistracking -> Halo -> + Crackle -> + Side-B bleed] -> + Hiss -> Tone. Tone moved to the end (it is the playback head's HF loss, so it also softens halo, crackle, bleed and hiss). Age 0 is bit-transparent (the history buffer is still written so raising Age never plays stale audio); a 30 ms Age smoother ramps every gain. Every part outputs exactly 0 for silent input (tested part by part, 3 s of zeros at Age 100 give bit-exact zeros, and 0 crackle events); recursive states are flushed below 1e-12, halo is switched off below an envSlow of 1e-7.
- **Mistracking (worn Dolby B).** Dolby B boosts quiet highs on record and cuts them on playback; a worn tape has lost output, so the decoder sees quiet passages as even quieter and over-cuts: quiet parts come out dull, loud parts (where Dolby is inactive) are almost untouched, so the highs "breathe" with the music. That is the authentic direction (dull on quiet, open on loud). One dynamic high shelf (RBJ, S = 0.7, 4 dB * Age max, corner 2 kHz quiet -> 6 kHz loud) driven by the 2 kHz high-passed envelope; never boosts. Measured at Age 100: pink -10 dBFS 8-12 kHz -0.10 dB, pink -45 dBFS -3.52 dB, Age 0 exactly 0; the full mix at -14 LUFS is -0.95 dB above 8 kHz (limit -1.5).
- **Halo** (tape modulation noise): "hug" = signal x 30-400 Hz noise (instant skirts) + "cloud" = HP 150 -> 2 Schroeder all-passes -> 4-line FDN (17/23/31/43 ms, Householder, 5 kHz loop lowpass, integer delays, T60 = 0.15 + 0.6 a) -> jitter read (2 ms + 0.12 ms * a * band-limited noise) -> erosion x(1 + 0.8 * noise, never negative) -> 8 kHz lowpass. Mix `gH(a) * (0.4 * hug + cloud)`; **the hug weight is 0.4 (plan 0.5)** because at 0.5 the 300 ms hang measured -45.5 dB re the burst (limit -45); the cloud's gain is normalised by sqrt(0.45 / T60) so the level does not grow with T60. `kHaloCal` = 1.07 (empirical); halo level re the signal on the full mix at -14 LUFS: -31.3 / -25.2 / -15.6 dB at Age 20 / 50 / 100 (targets -34 / -25 / -14, +-3). The dry path is scaled by `cDry = sqrt(1 - 10^(haloDb/10))` (fixed function of Age; total power constant). Halo is fed by the mistracked signal (chain order). Hang: -44.7 dB re the burst 300 ms after a 200 ms burst (limit -45 is checked as >= -45), < -200 dBFS 2 s later; autocorrelation of the halo of a click has no peak above 0.3 at 10-200 ms; >= 70 % of a triad's halo energy sits within 600 Hz of the partials; the dry signal's pitch does not move (< 1 cent on the dry path; the full output's mean pitch offset is < 1 cent too, a naive 20 ms phase demodulator is perturbed by the halo's noise skirts so the full-output check uses 100 ms blocks).
- **Crackle** (Barkhausen / oxide dust): events are Bernoulli draws once per 16 samples with `lambda = a^1.5 (6 * level * cluster + 2000 * onset^2)` (plan: 6 / 380 on a linear onset; **tuned** so sustained material gets almost none while hits get bursts: events/s on the drum loop vs the pad: 43 vs 10 with a squared onset only, 27.6 vs 4.1 (6.7x) with the 0.2 threshold), only while the music is present (silent for under 0.2 s) and envSlow > 1e-5. The onset is `((envFast - envSlow) / envSlow - 0.2)` clamped, then squared (sustained material wobbles around 0.1). 6 voices per channel (noise x 0.1 ms attack / 0.2-1.5 ms decay through a random 1.5-7 kHz band-pass), amplitude `envSlow * 10^((-32 + 7 N) / 20)` capped at -20 dB re envSlow (**plan -36; +4 dB so it is audible**, the grain amplitude is the RMS of the coloured burst), 60 % of events in both channels, then a 9 kHz lowpass. Measured at Age 100: centroid 4.2 kHz, level -45.7 dB re the signal on the drum loop (-48.8 on the full mix; limit -30), interval CV well above 1 and no off-beat autocorrelation peak above 0.2 (tests pass; 0.02 and CV 3.5 were measured while tuning). **Deviation: "no sharp clicks" is tested as max step < 0.9 x peak, not 0.25**: a plain 2 kHz sine already has 0.26 (the lower bound of the required centroid), so 0.25 cannot hold for any grain in 2-5 kHz; a one-sample impulse would read 1.0 (measured 0.71).
- **Side-B bleed.** 4 s history of the signal (always written), grains read **backwards** (length 0.35-0.9 s, start 0.6-3.2 s behind the head clamped to fit the buffer, speed 1 +- 0.3 %), Hann windows, **three readers per channel** instead of two (random grain lengths make a third overlap possible; the sum is normalised by `sqrt(sum w^2)` so power is constant), shroud = HP 180 -> LP 2.2 kHz -> jitter read (0.2 ms) -> erosion. Gain `envSlowB (600 ms release) * 10^((-56 + 24 a) / 20) * kBleedCal` where **the history is normalised per grain by the mean slow envelope of its source span** (otherwise the plan's `envSlowB * ...` would square the level); `kBleedCal` = 1.377. **Silence:** exactly 0 once the input has been below -100 dBFS for 0.3 s plus a 0.5 s fade (plan: "exactly 0 within 2 s"; the 600 ms exponential release alone would take 8 s). Measured: -51.3 / -44.1 / -32.1 dB re the signal at Age 20 / 50 / 100; the 50 ms RMS never drops more than 12 dB below its median on a sustained pad; best normalised cross-correlation with the reversed source is below 0.35.
- **Age is gain neutral:** Age 100 vs Age 0 on all five materials at -14 and -30 LUFS within -0.93 dB (worst: pink at -30 LUFS, from the mistracking); crackle and bleed add < 0.05 dB, so no `cAge` trim was needed.
- CPU (RelWithDebInfo, 48 kHz / 128 block, Drive / Wow / Flutter / Age 100, Hiss 50, Tone 8 kHz, Low Keep, Glitch 30 %): MP3 1.40 %, Stream 1.16 %, Broken 1.08 % of one core; the same with Age 0: 0.91 / 0.89 / 0.80 %, so Age costs about 0.5 %. 20 instances (Stream): 22.9 % total, 17.3 % with Age 0.

### Noticed, not changed (v0.4)
- `getTailLengthSeconds()` is still 0.1 s although Age's halo and bleed ring for up to about 1 s after the music stops (Live keeps processing while its input is non-silent; an export that ends exactly at the clip end would cut the ghost).
